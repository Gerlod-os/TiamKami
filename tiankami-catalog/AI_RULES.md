# Правила разработки для проекта Tiankami

## Стек технологий:

- React 19 (используй актуальный синтаксис, без устаревших defaultProps)
- Vite (сборщик)
- Tailwind CSS (для стилизации, используй только стандартные классы)
- React Router v7 (для навигации)
- Oxlint (для проверки кода, не используй ESLint правила)

## Строгие правила для ИИ:

1. Язык: Всегда отвечай и пиши комментарии в коде на РУССКОМ языке.
2. Полнота кода: НИКОГДА не используй заглушки вроде `// ...остальной код` или `// тут ваша логика`. Выдавай ВЕСЬ код файла от первой до последней строки.
3. Импорт: Всегда указывай полные и правильные пути импорта (например, `import { useState } from 'react'`).
4. Формат вывода: Сначала напиши точный путь к файлу (например, `src/components/Header.jsx`), затем дай полный код в одном блоке.
5. Безопасность: Не предлагай удалять существующие файлы `vite.config.js` или `package.json` без прямого запроса.
6. Данные: Все данные загружаются из Google Sheets и кэшируются в localStorage. Используй единые нормализаторы из `src/utils/normalize.js`. Даты в формате DD.MM.YYYY — парси через `src/utils/date.js` (parseRuDate).
7. Ссылки на игры: Используй `slugify()` из `src/utils/slugify.js` для генерации URL. Для уникальности используй `uniqueSlug()` при коллизиях.
8. Контекст: Суть проекта, архитектура и актуальный статус — в PROJECT_BRIEF.md. Инструкции по настройке (смена таблицы, API-ключ, передача прав) — в README.md. При противоречиях приоритет: PROJECT_BRIEF.md > README.md > этот файл.
9. Внешние API: только с кэшированием (см. README «Защита от блокировок»). Никаких запросов к Steam — только CDN по appid. Никаких автоповторов запросов.
10. Рабочий процесс: перед изменением логики/вектора — сначала описать, что собираешься делать, и получить согласие пользователя. После каждого блока изменений — проверка (npm run build + oxlint), в конце — комплексная проверка всего.
11. Личные данные канала (ник, ссылки, Twitch-логин) — только в src/config/branding.js. Ссылки на таблицу — только в src/config/dataSources.js. Не хардкодить их в компонентах.

## Известные особенности данных (мастер-таблица):

- Владелец пишет статус «Жду релиз» (без «а») — normalizeStatus приводит к «Жду релиза». Возможен и статус «В процессе».
- Гиперссылки (YouTube-плейлисты, МИ, Steam) при экспорте TSV/CSV теряются, остаются тексты-заглушки («Ссылка на плейлист»). Настоящие URL достаются через Sheets API (SHEETS_API_KEY) — см. loadData.js → fetchHyperlinks.
- Лист «Подборки от Тиана» свёрстан вручную: колонки «гуляют», ранги стоят через колонку и попадают в колонку следующего заголовка. Парсер normalizeCollections работает построчно — не переписывать на колоночный.
- У подборки «ЗОЛОТОЙ СПИСОК» рангов нет намеренно («Без рейтинга»).
- CSV листа подборок парсится запятой (gviz), лист игр — табуляцией (export TSV).
