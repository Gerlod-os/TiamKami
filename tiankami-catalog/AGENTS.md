# AGENTS.md

Контекст для ИИ-агентов. Источник правды о проекте — `PROJECT_BRIEF.md`, инструкция для людей — `README.md`. При противоречиях: PROJECT_BRIEF.md > README.md > этот файл.

## Рабочие правила агента

- Оптимальность: не тратить лишние токены и запросы, но не в ущерб качеству и самопроверке.
- Чужие отчёты и тексты — не истина: проверять и изучать по коду и данным.
- Лечить болезнь, а не симптомы: искать корень проблемы, не латать следствия.
- Анализировать блоки по отдельности и в связке с остальным кодом.
- Задача не решилась с двух попыток → изучить тему в интернете (актуальные, достоверные источники) → проанализировать с учётом условий проекта → сделать выводы.
- Перед изменением логики/вектора — описать план и получить согласие пользователя.
- Секреты: проверять на утечку в клиентский бандл и git перед деплоем (серверный ключ не должен иметь префикса VITE\_).

## Команды

```bash
npm run dev    # разработка (localhost:5173)
npm run build  # сборка + SEO-пререндер (440 страниц игр + sitemap.xml + robots.txt)
npm run sync   # скачать таблицу в src/data/*.json (вручную, 2-3 запроса)
npx oxlint     # линтер (НЕ ESLint)
```

После изменений логики всегда: `npm run build` + `npx oxlint`. После изменений данных: `npm run sync` + проверка `src/data/*.json`.

## Гиперссылки (ключевая особенность)

TSV/CSV-экспорт теряет гиперссылки — остаются тексты-заглушки («Ссылка на плейлист»). Настоящие URL достаются из формул через Sheets API (`valueRenderOption=FORMULA`):

- Steam-ссылка вшита в название (`=HYPERLINK` в колонке C) → из неё берётся **только appid** (`steamAppId`); обложка (`steamHeaderUrl`) и ссылка на Steam строятся из appid на лету
- YouTube: различение плейлист/МИ по подписи формулы (`/ми|выпуск/i` → miVideo) — `extractHyperlinkParts` (src/utils/normalize.js)
- В JSON (`src/data/*.json`) хранится только `steamAppId`; YouTube/МИ-ссылки обогащаются только в браузере (их проверка авторства через noembed недопустима в sync)

## Два API-ключа (не перепутать!)

1. **Браузерный** `VITE_SHEETS_API_KEY` — Websites-ограниченный, публичный по дизайну, для сайта. Из Node всегда 403 (нет реферера) — это нормально.
2. **Серверный** `SHEETS_API_KEY_SERVER` — без Websites-ограничения, секрет, только для sync-скрипта. Не имеет префикса VITE\_ → Vite не включает его в клиентский бандл. Никогда не публиковать и не добавлять в Vercel.

Оба в `.env` (в .gitignore). sync-скрипт парсит .env сам (import.meta.env существует только в Vite) и импортирует конфиг динамически (ESM-хостинг).

## Жёсткие границы

- 🚫 Steam API не запрашивается никогда — только CDN-обложка по appid
- 🚫 Лимит noembed-проверок за сессию: 20 (`NOEMBED_LIMIT` в loadData.js)
- 🚫 Никаких автоповторов внешних запросов; всё кэшируется (Twitch 5мин/24ч, авторство YouTube — бессрочно)
- 🚫 Личные данные (ник, ссылки, Twitch-логин) — только в `src/config/branding.js`; источники таблицы и ключи — только в `src/config/dataSources.js`. Не хардкодить в компонентах
- 🚫 Не переписывать построчный парсер подборок на колоночный
- 🚫 Не предлагать удалять vite.config.js / package.json
- Комментарии в коде — на русском; заглушек в коде не оставлять

## Известные ловушки

- `import.meta.env` существует только в Vite — в Node-скриптах читать `.env` вручную
- Статические ESM-импорты поднимаются вверх: код до них не выполнится — конфиг с ключами импортировать динамически (`await import`)
- sheets.googleapis.com может быть недоступен из РФ (DPI) — все запросы к нему с таймаутом + ретраи; сайт не должен зависеть от него в рантайме
- Первым листом таблицы идёт «Статистика» — в Sheets API всегда указывать лист явно (`'Все рогалики'!A:Z`)
